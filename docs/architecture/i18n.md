# Internationalization

The browser application supports Spanish (`es`), English (`en`) and French (`fr`).
It uses i18next and react-i18next, with bundled resources: switching language does
not fetch a translation service or send project data elsewhere.

## Language selection

An explicit choice in Settings → General takes priority. Otherwise, the app checks
`navigator.languages` in order, matching regional/script variants to their base
language (for example `es-AR`, `en-US`, `fr-CA`). Unsupported or malformed entries
are skipped; English is the fallback when none match. The selector's browser
option returns to automatic detection.

Only explicit choices are stored, under `t3-designer.language` in local storage.
Invalid stored values are ignored. If storage is unavailable, switching still
works for the current page session. Storage events synchronize open tabs;
`languagechange` events update automatic mode without overriding a manual choice.
`html[lang]` and the document title update with the interface.

`LanguageSettings.tsx` is an accessible native select in the shared settings modal.
Persistence and detection logic remain outside the panel. Native keyboard interaction,
autonyms and an associated label avoid flag/country ambiguity.

## Resource and domain boundaries

Resources live in `apps/web/src/i18n/locales/{es,en,fr}/`, with three namespaces:

| Namespace | Scope |
| --- | --- |
| `common` | App navigation, metadata and language settings |
| `workspace` | Apartment/building/solar controls, labels, fixtures and reconstruction notes |
| `dossier` | Dossier navigation, facts, sources, questions, observations and evidence presentation |

Canonical scene data remains unchanged by the selected language. Presentation
adapters reference stable room, fixture and dossier IDs. Geometry, source IDs,
URLs, raw public extracts, photographs, quoted source records and reproducible
Blender snapshots retain their original meaning and provenance. Original reference
downloads are source artifacts, not localized UI documents. Developer documentation
is organized by subject and is not duplicated per language.

The Spanish catalog defines the typed key structure. `i18next.d.ts` checks keys at
call sites; `resources.ts` checks catalog structure; the translation tests also
reject extra/missing keys, empty translations and mismatched interpolation names.
Resource text renders through React, without raw HTML injection. Plural messages
use i18next's `_one`/`_other` forms and a numeric `count` argument. Translate a
complete phrase instead of assembling sentence fragments in components.

Use `useTranslation(namespace)` for text and `useLocale()` for numeric, date and
compass formatting. **Language never changes the solar study timezone:** dates,
sunrise/sunset and clock labels use `Europe/Paris`, including DST. Form values
remain machine-readable ISO dates and 24-hour times. Dossier search uses localized
presentation text and ignores accents and case.

To add or change a message, update all three catalogs and every relevant consumer.
For new domain records, add their ID-based presentation entries as well. Do not
translate machine keys, route hashes or serialized model data. Preserve all
qualifiers distinguishing reported, observed, estimated and unverified information.

## Verification

```sh
pnpm check             # lint, typecheck, unit/contract tests, snapshots, build
pnpm --filter @t3-designer/web exec playwright install chromium
pnpm test:e2e          # browser integration suite
pnpm check:all         # both suites
```

The browser suite uses its own Vite server at `127.0.0.1:4173`; the port must be
free. It covers regional browser preferences, ordered negotiation, English
fallback, manual persistence, automatic reset, cross-tab updates, blocked storage,
all workspaces, state retention and mobile keyboard access. Most cases disable
WebGL to test fallback controls independently of the host GPU. Rendering-specific
tests explicitly enable Chromium's software WebGL path. Playwright artifacts are
retained on failure in a per-run `/tmp/t3-designer-i18n-results-*` directory, so
concurrent suites cannot delete each other's traces.

The framework follows [i18next typed resources](https://www.i18next.com/overview/typescript)
and [react-i18next hooks](https://react.i18next.com/latest/usetranslation-hook).
