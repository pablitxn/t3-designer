## Backend de QA reutilizable

`apps/api/test/owner-qa-backend.ts` es un ejecutable separado; **el entry point de produccion
no lo importa y ninguna variable del servidor normal habilita estos mocks**.
Requiere `NODE_ENV=development`, `T3_OWNER_QA=isolated-fixtures`, origin HTTP 127.0.0.1,
directorio bajo `artifacts/owner-qa/` y ausencia de claves, DB remota y OTLP externo.
La prueba `owner-qa.test.ts` comprueba rechazos antes de abrir storage.

Usa Better Auth, API HTTP, autorizacion, SQLite de cuentas/proyectos, biblioteca,
referencias, metering/ledger, workers, cola compartida y versiones/checkpoints reales.
Los generadores se inyectan desde `owner-qa-mocks.ts`; no llaman a OpenAI, Codex,
web search, fabricantes, catastro ni Blender. Las peticiones externas del navegador
se abortan en las pruebas propias.

Fixtures:

- `owner-standard@example.test`: usuario standard con trial y grant sintetico para muchos casos.
- `owner-premium@example.test`: premium regalado, sin rol admin.
- `viewer-qa@example.test`: otra cuenta standard para comprobar aislamiento.
- `qa-admin@example.test`: solo setup/revocacion de sesiones de datos ficticios.
- Password de todas estas cuentas ficticias: `Synthetic-QA-password-2026`.
- `seed.json` privado contiene invitaciones ficticias de demostracion. No se imprimen tokens.
- Las pruebas crean ademas identidades distintas por OWNER-ID y viewport (sufijos `-01-360`, `-01-430`, `-01-desktop`, etc.). Asi no comparten historial ni agotan artificialmente el throttling de login. Las cuentas manuales anteriores siguen disponibles.
- Todos los proyectos empiezan vacios y se crean por UI. Snapshot rectangular determinista de 8x6 m.
- `[qa:needs-input]` en instrucciones/notas: pide aclaracion; una respuesta sin esta marca permite continuar fundamentos.
  En mobiliario pide dimensiones hasta recibir las tres.
- `[qa:failed]`: falla el primer intento por proyecto/target/mensaje (fundamentos) o URL (mueble); retry en el mismo proceso termina.
- `[qa:slow]`: permanece en curso hasta cancelacion o 30 s; permite observar running/queued sin esperar artificialmente.
- Sin marca: success rapido. Cancelled y retry pasan por la API/worker reales.
- GLB: bytes del modelo existente `fridge-freezer.glb`. PNG: fixture minimo. `.blend`: texto marcado fixture,
  no archivo Blender utilizable. Manifest sintetico con hashes reales y `qaFixture: true`.
  Esto prueba publicacion/descargas/integridad, **no** dimensiones ni fidelidad del GLB ni calidad de generacion.

La instancia de QA informa capacidades sinteticas en `/api/health` para desbloquear
los controles del taller; esos campos no acreditan auth externa ni disponibilidad real de Blender.
Los mocks no instrumentan llamadas de proveedor; uso/costos de producto siguen persistidos, tokens reales no existen.
Los limites altos y grants estan solo en fixtures; no se modificaron gates ni defaults productivos.
El perfil de esta tanda usa BillingService real en modo disabled; no usa transporte de pagos.
