## Reusable QA backend

`apps/api/test/owner-qa-backend.ts` is a separate executable; **production entrypoint
does not import it, and no normal-server variable enables mocks**. Requires
`NODE_ENV=development`, `T3_OWNER_QA=isolated-fixtures`, HTTP 127.0.0.1 origin,
`artifacts/owner-qa/` directory and absent keys/remote DB/external OTLP.
`owner-qa.test.ts` verifies rejection before opening storage.

Uses real Better Auth, HTTP API, authorization, account/project SQLite, library,
references, metering/ledger, workers/shared queue and versions/checkpoints.
Injected `owner-qa-mocks.ts` generators call no OpenAI, Codex, web search,
manufacturer, cadastre or Blender. Own tests abort external browser requests.

Fixtures:

- `owner-standard@example.test`: standard trial user with synthetic many-case grant.
- `owner-premium@example.test`: gifted premium, no admin role.
- `viewer-qa@example.test`: other standard account for isolation.
- `qa-admin@example.test`: fictional setup/session revocation only.
- All fictional-account password: `Synthetic-QA-password-2026`.
- Private `seed.json` contains fictional demo invitations; tokens not printed.
- Tests additionally create identities per OWNER-ID/viewport (`-01-360`, `-01-430`,
  `-01-desktop`, etc.) to separate history/login throttling; manual accounts remain.
- Projects start empty, created through UI; deterministic rectangular 8x6 m snapshot.
- `[qa:needs-input]` instructions/notes request clarification; answer without mark
  continues foundations. Furniture requests all three dimensions.
- `[qa:failed]` fails first foundations attempt per project/target/message or
  furniture URL; retry in same process completes.
- `[qa:slow]` runs until cancellation or 30 s, exposing running/queued naturally.
- No mark: fast success. Cancellation/retry use real API/worker.
- GLB bytes from existing `fridge-freezer.glb`; minimal PNG; `.blend` text explicitly
  marked fixture, not usable Blender file. Synthetic manifest with real hashes,
  `qaFixture: true`. Tests publication/download/integrity, **not** GLB dimensions,
  fidelity or generation quality.

QA `/api/health` reports synthetic capabilities to unlock workshop controls,
not external auth or actual Blender availability. Mocks instrument no provider
calls; product usage/costs persist, real tokens absent. High limits/grants only
in fixtures, no production-default/gate changes. Real BillingService disabled,
no payment transport.

## Reproduce without real credentials

Repo Node/pnpm/dependencies, from T3 root:

```sh
# In this Cloud first: source /workspace/.cloud-setup/activate.sh
pnpm --filter @t3-designer/web exec playwright test --config playwright.owner.config.ts
# Single viewport:
pnpm --filter @t3-designer/web exec playwright test --config playwright.owner.config.ts --project chromium-touch-360
```

`T3_QA_CHROMIUM` selects installed executable; Cloud explicitly `/usr/bin/chromium`.
Integration default is official Playwright binary. Tests start/stop API 8798 and
Vite 4189, fail if another server exists and never terminate others' processes.
Each run creates a new dataset.

For persistent manual session, two terminals and new directory:

```sh
# Terminal 1 (does not load .env):
env -u OPENAI_API_KEY -u CODEX_API_KEY -u T3_DATABASE_URL -u OTEL_EXPORTER_OTLP_ENDPOINT \
  NODE_ENV=development T3_OWNER_QA=isolated-fixtures \
  T3_QA_DIRECTORY=artifacts/owner-qa/manual-20261013 \
  node apps/api/test/owner-qa-backend.ts

# Terminal 2:
T3_API_PROXY_URL=http://127.0.0.1:8798 \
  pnpm --filter @t3-designer/web dev:full --host 127.0.0.1 --port 4189 --strictPort
```

Open local `/login` on 127.0.0.1:4189 with chosen fictional account. Publish no
preview/activation links. Ctrl-C only own processes. Disable mocks by stopping
**this** backend and using normal `apps/api/src/index.ts` with isolated development
configuration and generation disabled. Never reuse QA directories/accounts as
production data. Restart with another directory; deletion unnecessary.

Manual checklist:

1. Standard login; create project, check empty fields/closed editor.
2. Upload PNG, add basement -1 and fictional address/source; save/reload.
3. Edit notes in two tabs; save first, verify second conflict.
4. Leave draft; cancel link/Back departure, retain route/notes.
5. Home `[qa:needs-input]`, answer/accept; building start/accept.
6. Duplicate variant/layout; create/attach/place synthetic asset, change finish,
   save/reload.
7. Submit correction; cancel replacement, retain base; accept/check checkpoint.
8. `[qa:slow]` observe queue/cancel/refund; `[qa:failed]` retry.
9. Share with viewer-qa; inspect separate-profile reading, change editor/revoke.
10. Download fixture GLB/manifest; logout/premium login/check invitations.
